## Widevine / castlabs Electron (ECS)

Parachord is built on [castlabs Electron for Content Security](https://github.com/castlabs/electron-releases), not stock Electron (`package.json` `devDependencies.electron` is a GitHub URL with a `+wvcus` tag; electron-builder downloads the matching binary via `build.electronDownload.mirror`). **Stock Electron has no Widevine at all.** The old `--widevine-cdm-path` block in main.js that tried to borrow a browser's CDM did nothing (the switch no longer exists in Electron), which is why Apple Music through MusicKit JS on Windows/Linux only ever played 30-second previews (parachord#882). Tracking issue with the spike results: parachord#988; landed in #989, shipped in v0.9.8.

- **Startup:** `waitForWidevine()` (main.js, called first thing in the `app.whenReady` handler) awaits `components.whenReady()` with a 10s cap, then the rest of startup runs in the old order. It's a no-op on stock Electron (`components` undefined). Don't move window creation ahead of it: a page already open may not pick up a CDM that finishes installing later.
- **VMP signing is what makes production licence servers accept the build.** castlabs' prebuilt binaries are signed for development only: Widevine's test servers and the Amazon Music web player accept that, Apple's licence server refuses it (`MEDIA_LICENSE`). `scripts/vmp-sign.js` production-signs via `python -m castlabs_evs.vmp sign-pkg --streaming`. **Order is platform-specific and load-bearing:** macOS before Apple code signing (`scripts/after-pack.js`), Windows after Authenticode (`scripts/after-sign.js`, which then hands off to `scripts/notarize.js`). Linux has no VMP. Verified on v0.9.8: app, zip and DMG notarize, staple and pass Gatekeeper with the VMP `.sig` in place.
- **EVS account:** free, named `parachord`. CI logs in every run from `EVS_ACCOUNT_NAME` / `EVS_PASSWD` (tokens expire monthly). `EVS_REQUIRED=1` is set on release tags so a tag can't ship with the dev signature; other builds (including fork PRs with no secrets) warn and keep it. Locally, `python3 -m castlabs_evs.account reauth` once, then `EVS_PYTHON=<python with castlabs-evs>` for the hooks.
- **What Widevine does and doesn't give us:** Amazon's web player can stream its lossless tier once the build has a **production** VMP signature. A development signature is not enough: `POST /NA/api/dmls/` returns 400 `DrmLicenseDeniedException` / `UNTRUSTED_DEVICE_CERTIFICATE` / `DEVELOPMENT_CERTIFICATE_NOT_ALLOWED` (verified 2026-10 against hornet 1.181). Apple via MusicKit JS stays at 256 kbps AAC (no lossless on Apple's web stack, no ALAC in Chromium) and also refuses the development signature. macOS Apple Music uses the native MusicKit helper, not Widevine. See castlabs' [VMP Lab](https://castlabs.github.io/wv-vmp-lab/) for a build's status.
- **Version tracking:** castlabs tags follow stock Electron (`v44.5.1+wvcus`). Their supported majors are the three latest (44/43/42 as of 2026-10); 44 is the newest of them, fully in the support window. Bump together with the electron-builder upgrade, and run `npx electron-builder install-app-deps` after changing it so `better-sqlite3` is rebuilt.

## Local server port (OAuth callbacks + `/protocol` bridge)

One loopback Express server (`startAuthServer`, main.js) serves the Spotify (`/callback`) and SoundCloud (`/callback/soundcloud`) OAuth redirects AND the `parachord://` HTTP bridge (`/protocol`, used by Raycast and curl). Its port is a user setting since parachord#958: Settings → General → Local Server Port, stored as `oauth_callback_port`, resolved once at startup as stored → `AUTH_SERVER_PORT` env → 8888 (`main-process/auth-port.js`, pure + tested; 1024–65535, never 9876, the extension server's port). It applies on the next launch, so **redirect URIs always use the BOUND port** (`authServerState.port`), never a just-saved one, or a sign-in before the restart would go to a port nothing listens on. Spotify's authorize request and token exchange both call `spotifyRedirectUri()` (Spotify rejects the exchange unless the two are byte-identical; `SPOTIFY_REDIRECT_URI` is a dev override that wins verbatim and is warned about when its port differs). Don't hardcode `8888` anywhere a redirect URI or the bridge URL is built: `tests/main-process/auth-port.test.js` fails on one in main.js or the renderer. The port is user-chosen, never auto-picked, because providers match the redirect URI exactly, port included: an unregistered port fails sign-in with no visible cause. SoundCloud has no loopback-port exception and Parachord's bundled SoundCloud app is registered at :8888, so on another port `soundcloud-auth` refuses up front with an explanation unless the user's own SoundCloud credentials are set (`soundCloudSignInAllowed`); token refresh sends no redirect URI and keeps working. A bind failure (EADDRINUSE) used to be silent; it is now kept in `authServerState.error` (the renderer reads it on mount, the failure usually precedes the window) and pushed as `auth-server:error`, and the renderer shows a persistent toast pointing at the setting. Express 5's `app.listen` callback also fires on a bind failure, with the error, so it must ignore that case. IPC: `auth-server:get-status` / `auth-server:set-port` (`main-process/ipc/auth-server.js`; validation errors come back as `message`, because `error` is the bind error). The Raycast extension still assumes 8888 (documented in docs/protocol-schema.md). Design: `docs/plans/2026-07-01-configurable-oauth-callback-port-958.md`.
